## Storage 设计检查（SDK v2.4.9/rev29）

| 项目 | 结论 | 依据 |
|---|---|---|
| S1 单值大小 | pass | 历史与回退有上限；测试包含 400 条长对白和 100 个回退检查点，序列化小于 220 KiB，低于文档 256 KiB 限制。正常实玩约 130 段以内。 |
| S2 key 上界 | pass | 每玩家固定 9 个 user key：profile、auto、quick、6 个普通槽；没有 game scope 写入。 |
| S3 写入频率 | pass | 自动存档合并选择事件并限制约 10.5 秒间隔；不从渲染循环写入。一次存档与图鉴各一个值。 |
| S4 scope | pass | 平台读取、保存和删除显式使用 user。 |
| S5 并发 | pass | 平台适配器串行写入，读取 version 并用 ifVersion；冲突可见，不盲目覆盖。 |
| S6 失败处理 | pass | 存读档捕获异常；使用 isPlatformSDKError 区分冲突、登录、限流、容量、配额；失败不提示保存成功，游戏内存可继续。 |

## 草稿 HTTP 静态检查（2026-10-19）

使用本轮获取的草稿元数据，对入口、封面与 38 个包资源共 40 项进行一次有界检查，并发为 6；HEAD 返回 403/405/501 时补一次仅请求首字节的 Range GET，无超时或无限重试。

| 检查 | 实测结果 |
|---|---|
| 40 项元数据地址的 HEAD | 12 项 200，28 项 403 |
| 对上述 28 项的 Range GET | 9 项 206，19 项仍为 403 |
| 40 项最终 HTTP 结果 | 21 项 200/206，19 项 403；成功项内容类型符合对应文件类型 |
| 本地构建路径对照 | 39/39 文件在元数据中匹配；38/38 包资源与入口相对基础路径一致 |
| 签名入口的普通 GET | 403，未能读取远端 HTML，未比对其正文或引用与本地入口是否相同 |
| 按本地入口相对引用解析的 `game/style.css` 与 `game/app.js` | 地址未继承入口 query，普通 GET 均为 200，分别为 `text/css`、`text/javascript`；其中 `app.js` HEAD 为 403 |

这些是特定时间、方法和地址形式下的 HTTP 观察。HEAD、Range GET 与普通浏览器 GET 的结果不能互相代替，仍不能证明整个游戏包能在平台中完整加载。完整记录见 [draft-verification.json](draft-verification.json)；公开记录只保存资源相对路径，不包含签名 URL、查询参数或私密元数据。
